# Capability Process Evaluation

> Type: Reference
> Status: Active
> Scope: Lightweight evaluation of capability overhead and reusable process improvements

Evaluate completed work only when there is useful evidence. Keep capability use lighter than the value it adds.

Preferred improvement order:

remove duplication -> simplify -> merge rules -> automate deterministic work -> add capability

Ask whether a capability was invoked without a real trigger, whether native reasoning would have been simpler, whether context was loaded repeatedly, whether delegation added overhead, and whether verification was proportional to risk.

Never weaken security, permission, branch, verification, redaction, or release controls merely to reduce friction.

Record at most one reusable improvement and do not recursively create process-improvement work.
