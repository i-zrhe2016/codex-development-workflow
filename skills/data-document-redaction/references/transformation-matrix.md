# 变换选择矩阵

把“脱敏”当成风险与效用的取舍，而不是一个固定算法。先问交付者是否需要识别同一主体、重放业务规则或保留统计分布，再选最小充分变换。

| 操作 | 可逆性/可链接性 | 适合场景 | 主要风险 |
|---|---|---|---|
| 删除/抑制 | 不可逆（对已删除字段） | 公开发布、对外样例 | 可能破坏分析或关联；要同步检查外键与公式 |
| 固定掩码（如 `***1234`） | 通常可链接；部分值仍暴露 | 人工审阅、客服工单 | 末尾数字、长度和格式可能重识别；不是匿名化 |
| 随机替换 | 若不保留映射则不可逆 | 对外测试数据、演示 | 需避免碰撞、非法格式和跨表不一致 |
| 令牌化/伪名化 | 可逆或可链接（有映射/密钥） | 内部排障、跨文件追踪 | 映射泄漏、低熵值可被猜测；仍按个人数据治理 |
| 哈希/HMAC | 同值可链接；低熵输入可枚举 | 去重、短期关联 | 公开盐/密钥或字典攻击；不能直接称匿名化 |
| 泛化/分箱 | 通常不可逆 | 年龄、日期、地域、金额分析 | 组合准标识符仍可唯一定位；稀有桶需抑制 |
| 聚合/阈值发布 | 不可逆（若无小群体输出） | 统计报表、公开指标 | 小样本、差分查询和极值泄露 |
| 扰动/噪声 | 通常不可逆 | 趋势或模型训练 | 可能破坏业务约束；需测量误差与隐私预算 |
| 合成数据 | 不应含真实行的可回溯映射 | CI、演示、一般测试 | 分布/异常值不真实；必须验证关系和覆盖度 |

## 字段级默认规则

| 类型 | 默认处理 | 说明 |
|---|---|---|
| 姓名、用户名、签名、头像 | 随机替换或删除 | 不要只改显示名；检查评论、作者、文件名和图片像素 |
| 邮箱、电话、账号 | 随机且格式合法的替换；外部发布删除 | 同一主体若需关联，使用隔离的随机令牌映射；不要使用真实域名/号码 |
| 身份证、护照、银行卡、社保号 | 删除或整段替换 | 部分掩码仍可能暴露校验位、国家和末尾数字；银行卡只保留经批准的最小位数 |
| 地址、邮编、经纬度、IP、设备标识 | 降低精度或删除 | 先评估与时间、职业、事件组合后的唯一性；IP 也可能是个人数据 |
| 日期/时间 | 截断到月/周/日或做一致平移 | 保留相对顺序时对同一数据集使用同一平移；不要泄露出生日期和精确事件时间 |
| 金额、年龄、工资、测量值 | 分箱、范围化或受控扰动 | 保留业务阈值前先验证极值、总额和小群体风险 |
| 自由文本、日志、堆栈、URL | NER + 规则 + 人工抽样 | 检查 base64/hex、查询参数、请求头、环境变量、异常消息和引用内容 |
| 密码、API key、JWT、私钥、Cookie | 删除并轮换真实凭据 | 不要把秘密替换成看似真实的可用凭据；输出中只给类型和位置 |
| 医疗、财务、法律、员工属性 | 按用途删除、分组或合成 | 与准标识符联合评估；必要时只在受控环境提供查询接口 |

## 保持关系但不保留身份

1. 先画出实体、主键、外键和唯一约束；不要按列各自随机化。
2. 为每个实体生成一次随机替换表，并把所有引用该实体的列映射到同一替换值。
3. 原始主键若本身是业务标识符，也要替换；内部技术键只有在确实不暴露且不会跨环境碰撞时才保留。
4. 映射表、种子和密钥不放在输出目录、日志、备份或版本库；需要可逆时交给独立的密钥/权限系统。
5. 重新执行外键、唯一性、行数、空值率、分布、业务规则和跨表 join 检查。若为性能复现，还要保留真实的偏斜和异常值，而不是把数据“平均化”。

## 风险判断

- 直接标识符被删除并不等于匿名化；年龄、日期、邮编、地点、职业和稀有事件的组合可能仍然唯一。
- 先确定发布对象拥有的外部数据、攻击者动机和可接受风险，再决定泛化粒度或是否抑制小群体。
- `k`-匿名、`l`-多样性或差分隐私是评估工具，不是自动合规证明；记录参数、假设和残余风险。
- 对公开数据优先减少字段和样本，再考虑复杂的噪声算法；复杂算法若无法复核，不应成为安全借口。
